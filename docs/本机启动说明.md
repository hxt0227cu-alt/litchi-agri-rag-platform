# 本机启动说明

本文档用于在不依赖 Docker 前端/后端容器的情况下，本机启动荔枝智能问答与协同诊断平台。

如果只想完整一键启动演示环境，推荐使用根目录 Docker Compose：

```powershell
cd <your-workspace>\hxt-bishe
Copy-Item .env.example .env
docker compose up -d --build
```

Docker 模式启动后访问 `http://localhost:8081`。

## 1. 前置依赖

请先确保以下服务已经可用：
- MySQL 8.0
- Neo4j 5.15-community
- Milvus v2.3.3
- Ollama（默认模型：qwen2.5:0.5b）
- `diagnosis-service`（Python 3.11 + Pillow >= 10.0.0 + Ultralytics >= 8.3.0）

推荐优先参考 [环境安装指南](./环境安装指南.md) 完成准备。

## 2. 本机启动顺序

### 2.1 启动基础依赖

确认以下地址可访问：

- MySQL：`127.0.0.1:3306`
- Neo4j：`127.0.0.1:7687`
- Milvus：`127.0.0.1:19530`
- Ollama：`http://127.0.0.1:11434`
- 识别服务：`http://127.0.0.1:8090`

### 2.2 准备 Ollama 模型

```bash
ollama pull qwen2.5:0.5b
```

### 2.3 启动病害识别服务

```bash
cd diagnosis-service
pip install -r requirements.txt
python server.py
```

如果没有正式模型文件，服务会运行在降级模式。

### 2.4 启动后端

```bash
cd backend
mvn spring-boot:run
```

说明：

- `application-dev.yml` 下，`APP_MYSQL_ENABLED` 默认为 `false`
- 如果你希望本机直接使用 MySQL，请先设置对应环境变量

Windows PowerShell 示例：

```powershell
$env:APP_MYSQL_ENABLED='true'
$env:APP_MYSQL_URL='jdbc:mysql://127.0.0.1:3306/litchi_platform?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false'
$env:APP_MYSQL_USERNAME='litchi'
$env:APP_MYSQL_PASSWORD='litchi123456'
```

如果希望启动后自动完成图谱、向量和样例文档准备，可设置：

```powershell
$env:APP_STARTUP_AUTO_BOOTSTRAP='true'
```

然后再执行：

```powershell
mvn spring-boot:run
```

如果只想手动初始化图谱和向量，也可以使用：

```bash
mvn spring-boot:run -Dspring-boot.run.arguments="--init=all"
```

### 2.5 启动前端

```bash
cd frontend
npm install
npm run dev
```

启动后访问：

- 前端：`http://localhost:5173`
- 后端：`http://localhost:8080/api`

## 4. 首次使用建议

如果本机没有开启 `APP_STARTUP_AUTO_BOOTSTRAP=true`，建议第一次启动按下面顺序操作：

1. 用技术员账号登录平台。
2. 进入技术支持台或系统状态页，确认服务状态。
3. 必要时调用初始化接口或执行重建平台样例。
4. 再切换到农户和门店账号进行完整链路验证。

## 5. 推荐本机验证流程

### 5.1 农户链路

1. 用 `farmer` 登录，确认默认进入 `/farmer/workbench`
2. 进入学习课堂，确认卡片正常加载
3. 进入病害识别页，用样图触发识别
4. 进入智能问答页提问，确认有来源卡片
5. 进入解决方案页，确认能看到推荐方案
6. 提交一条求助，确认“我的求助”中出现记录

### 5.2 门店链路

1. 用 `shopkeeper` 登录，确认默认进入 `/shop/workbench`
2. 打开店铺管理页，检查资料是否可保存
3. 打开配药方案页，确认能新增或编辑方案
4. 打开待处理求助页，确认能看到农户提交的记录
5. 把求助状态更新为“已联系”或“已完成”

### 5.3 技术员链路

1. 用 `technician` 登录，确认默认进入 `/technician/workbench`
2. 打开知识文档页，确认样例文档或上传入口正常
3. 打开研判图谱页，搜索“炭疽病”或“桂味”
4. 打开评测中心，确认题库可加载
5. 打开系统状态页，确认服务状态和设置摘要正常

## 6. 手动接口验证

### 6.1 健康检查

```bash
curl http://localhost:8080/api/health
```

### 6.2 手动初始化图谱与向量

如果你已经拿到技术员登录 token，可以调用：

```bash
curl -X POST "http://localhost:8080/api/system/init?scope=all" ^
  -H "Authorization: Bearer <token>"
```

### 6.3 手动重建平台样例

```bash
curl -X POST "http://localhost:8080/api/system/demo/bootstrap" ^
  -H "Authorization: Bearer <token>"
```

### 6.4 测试推荐方案

```bash
curl "http://localhost:8080/api/plans/recommendations?diseaseTag=%E7%82%AD%E7%96%BD%E7%97%85" ^
  -H "Authorization: Bearer <token>"
```

### 6.5 执行三角色主链路彩排脚本

```powershell
powershell -ExecutionPolicy Bypass -File scripts/rehearse-main-flow.ps1
```

说明：

- 该脚本会自动完成健康检查、三角色登录、识别、问答、方案推荐、提交求助、门店更新状态和技术员系统检查
- 执行完成后会把彩排报告写入 `reports/rehearsal/`

## 7. 常见说明

- 文档上传当前支持 `txt`、`md`、`pdf`、`docx`
- 本机开发默认是前后端分开运行，角色权限仍然完整生效
- 如果 Milvus 不可用，问答会回退到本地分块检索
- 如果识别模型不可用，识别服务会进入演示级降级模式
- 若启用 MySQL，协同模块和满意度反馈会一并写入结构化表；本地 `data/*.json` 继续保留回退副本
