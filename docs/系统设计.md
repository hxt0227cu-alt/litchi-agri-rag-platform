# 系统设计文档

## 1. 系统定位

荔枝智能诊断平台面向荔枝种植、农技服务和农资服务场景，提供统一的账号体系、知识问答、知识图谱、病害识别、文档管理、评测中心和系统运维入口。当前实现已经支持本机运行和 Docker 全栈运行两种方式。

## 2. 总体架构

平台采用前后端分离架构，并将知识图谱、向量检索、大模型推理、病害识别拆分为独立服务。

```text
浏览器前端 Vue 3
    ↓ HTTP / JSON
Spring Boot 后端 API
    ├─ 认证与角色权限
    ├─ 问答与会话历史
    ├─ 文档解析与向量检索
    ├─ 知识图谱查询
    ├─ 病害识别代理
    ├─ 评测中心
    └─ 系统初始化与健康检查

后端依赖的外部服务
    ├─ MySQL 8：业务主存储
    ├─ Neo4j 5：知识图谱
    ├─ Milvus 2：向量索引
    ├─ Ollama：大模型推理
    └─ diagnosis-service：病害识别 HTTP 服务
```

## 3. 技术栈

| 层级 | 技术选型 |
| --- | --- |
| 前端 | Vue 3 + TypeScript + Pinia + Vue Router + Element Plus |
| 后端 | Spring Boot 3.x |
| 认证 | 自定义 Token 鉴权 + 拦截器 + 角色注解 |
| 关系存储 | MySQL 8 |
| 图数据库 | Neo4j 5.15 |
| 向量数据库 | Milvus 2.3 |
| 大模型服务 | Ollama，默认模型 `qwen2.5:0.5b` |
| 文档解析 | PDFBox、Apache POI |
| 病害识别 | Python HTTP 服务，支持正式模型和保障模式回退 |
| 语音能力 | 浏览器 Web Speech API 与前端朗读能力 |

## 4. 核心模块

### 4.1 认证与权限

- 提供注册、登录、登出、当前用户信息接口。
- 当前内置三类角色：`farmer`、`technician`、`shopkeeper`。
- 权限控制通过 `@AuthRequired` 和 `@RoleAllowed` 在后端统一生效，前端菜单和路由同步限制。
- 评测中心和培训课堂仅技术员可访问；病害识别允许农户和技术员访问；用药指南允许技术员和农资店访问；系统初始化仅技术员可执行。

### 4.2 智能问答与会话历史

- 问答接口支持向量检索增强与知识图谱增强开关。
- 会话历史按用户维度保存，支持会话列表和分页历史查询。
- 聊天响应包含答案、文档来源片段、图谱命中实体。
- 当前图谱增强与 `/api/kg/search` 已统一复用同一套实体召回逻辑。

### 4.3 文档管理与检索

- 支持上传 `txt`、`md`、`pdf`、`docx`。
- 文档会进行文本抽取、分块、向量化，并写入本地状态与 MySQL。
- PDF 解析使用 PDFBox，DOCX 解析使用 Apache POI。
- 当 Milvus 未命中时，仍可回退到本地分块检索，保证问答链路可用。

### 4.4 知识图谱

- 图谱实体包括品种、病害、虫害、农药、栽培技术等。
- 图谱服务支持可视化、关键词搜索、实体详情查询。
- 启动初始化时会把内置平台样例节点和关系合并到 Neo4j。
- 自然语言图谱检索支持别名归一、关键词提取和多字段匹配。

### 4.5 病害识别

- 前端提供识别工作台，支持样图选择和本地图片上传。
- 后端将图片转发给独立的 `diagnosis-service`。
- 当正式模型不可用时，会进入保障模式返回可展示结果，保证平台可用性。

### 4.6 评测中心

- 支持题库分页、系统答案提交、人工评分、统计汇总。
- 评测数据当前持久化到 MySQL 标准业务表。
- 评测模块仅技术员角色开放。

### 4.7 系统初始化与运维

- 提供 `/api/health`、`/api/system/overview`、`/api/system/init`、`/api/system/demo/bootstrap`。
- Docker 环境下已支持自动启动引导：
  - 自动准备样例文档
  - 自动初始化知识图谱
  - 自动初始化向量集合并同步分块
- 新环境首次启动后即可直接进行问答和图谱演示。

### 4.8 培训课堂与用药指南

- 技术员可进入培训课堂页，查看样例知识、推荐问题和标准讲解流程。
- 农资店与技术员可进入用药指南页，按病害/虫害/综合场景快速查看药剂建议和沟通提醒。
- 两类页面都直接复用平台现有问答、图谱与样例资料，适合作为培训和门店接待入口。

### 4.9 满意度问卷

- 所有已登录用户都可提交满意度问卷，覆盖总体满意度、准确性、实用性和流畅性评分。
- 技术员可查看问卷统计汇总和最近反馈，作为后续优化依据。

## 5. 数据存储设计

### 5.1 MySQL 业务表

当前主业务数据存储在以下表中：

- `platform_users`
- `platform_sessions`
- `platform_chat_messages`
- `platform_evaluations`
- `platform_documents`
- `platform_document_chunks`

这些表分别负责用户、登录态、聊天消息、评测记录、文档元数据和文档分块。

### 5.2 其他存储

- Neo4j：保存图谱实体与关系。
- Milvus：保存文档分块向量。
- 后端本地目录：保存上传原文件与本地状态回退文件。

## 8. 部署形态

### 8.1 本机开发

- 本机启动 MySQL、Neo4j、Milvus、Ollama、识别服务
- 本机运行 Spring Boot 和 Vue 前端

### 8.2 Docker 全栈

`docker-compose.yml` 当前编排的服务包括：

- `mysql`
- `neo4j`
- `etcd`
- `minio`
- `milvus`
- `ollama`
- `ollama-model-init`
- `diagnosis-service`
- `backend`
- `frontend`

## 9. 当前设计特点

- 业务主存储已从快照表迁移到标准化 MySQL 表。
- 平台支持角色权限控制和完整页面导航。
- Docker 启动后具备自动引导能力，不再依赖手动演示初始化。
- 文档检索、图谱检索、病害识别都保留了保障模式，能提升弱依赖环境下的可用性。
