# 环境安装指南

本文档说明如何为荔枝智能问答与协同诊断平台准备本机开发环境。推荐优先使用 Docker 运行整套依赖；如果需要本机开发调试前端、后端或识别服务，再按下文安装对应组件。

## 1. 最低建议环境

| 项目 | 建议版本 |
| --- | --- |
| Java | JDK 17 |
| Maven | 3.9+ |
| Node.js | 20+ |
| Python | 3.11+ |
| Docker Desktop / Docker Engine | 24+ |
| Docker Compose | 2.20+ |
| MySQL | 8.0 |
| Neo4j | 5.15-community |
| Milvus | v2.3.3 |
| Ollama | 最新稳定版（默认模型：qwen2.5:0.5b） |

## 2. 推荐方式：Docker 一键环境

### 2.1 准备环境变量

在项目根目录复制环境变量示例：

```powershell
Copy-Item .env.example .env
```

或 Linux / macOS：

```bash
cp .env.example .env
```

### 2.2 启动全栈

```bash
docker compose up -d --build
```

启动完成后可访问：

- 前端：`http://localhost:8081`
- 后端 API：`http://localhost:8080/api`
- Neo4j Browser：`http://localhost:7474`
- MySQL：`127.0.0.1:3306`
- Ollama：`http://localhost:11434`
- 识别服务：`http://localhost:8090/health`

根目录 Compose 默认使用 `8081:80` 暴露前端，避免占用宿主机 80 端口。

### 2.3 Docker 模式下的自动初始化

当前 Docker 配置默认开启以下能力：

- `APP_STARTUP_AUTO_BOOTSTRAP=true`
- 自动初始化知识图谱
- 自动初始化向量集合
- 自动导入平台样例文档
- 自动拉取默认 Ollama 模型

相关环境变量：

- `APP_STARTUP_AUTO_BOOTSTRAP`
- `APP_STARTUP_MAX_ATTEMPTS`
- `APP_STARTUP_RETRY_DELAY_MS`
- `OLLAMA_CHAT_MODEL`

## 3. 本机开发依赖安装

### 3.1 Java

确认本机安装 JDK 17+：

```bash
java -version
javac -version
```

### 3.2 Node.js

确认本机安装 Node.js 20+：

```bash
node --version
npm --version
```

### 3.3 Python

确认本机安装 Python 3.10+：

```bash
python --version
pip --version
```

可选创建虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3.4 MySQL

平台当前使用 MySQL 作为核心结构化业务存储，默认库和账号示例如下：

- 数据库：`litchi_platform`
- 用户：`litchi`
- 密码：`litchi123456`

如果你使用本机已有 MySQL，也可以通过环境变量覆盖：

- `APP_MYSQL_URL`
- `APP_MYSQL_USERNAME`
- `APP_MYSQL_PASSWORD`

### 3.5 Neo4j

本机开发默认配置：

- Bolt 地址：`bolt://127.0.0.1:7687`
- 用户名：`neo4j`
- 密码：`litchi123456`

### 3.6 Milvus

本机开发默认配置：

- 地址：`127.0.0.1:19530`
- 集合名：`litchi_knowledge`

如果你不想手动部署 Milvus，建议直接使用 Docker Compose，因为 Compose 已经同时编排了 `etcd` 和 `minio`。

### 3.7 Ollama

安装完成后确认：

```bash
ollama --version
ollama list
```

平台默认模型为：

```bash
ollama pull qwen2.5:0.5b
```

也可以手动验证：

```bash
ollama run qwen2.5:0.5b
```

### 3.8 病害识别服务

识别服务位于 `diagnosis-service/`，可单独安装依赖：

```bash
cd diagnosis-service
pip install -r requirements.txt
```

如需启用正式模型，请把模型文件放到：

```text
models/yolov8-litchi.pt
```

如果模型不可用，平台会自动退回数据集特征匹配或规则兜底模式。

## 4. 本机开发配置

后端本机开发主要读取 `backend/src/main/resources/application-dev.yml`，可通过环境变量覆盖：

- `APP_MYSQL_ENABLED`
- `APP_MYSQL_URL`
- `APP_MYSQL_USERNAME`
- `APP_MYSQL_PASSWORD`
- `SPRING_NEO4J_URI`
- `SPRING_NEO4J_AUTHENTICATION_USERNAME`
- `SPRING_NEO4J_AUTHENTICATION_PASSWORD`
- `SPRING_AI_OLLAMA_BASE_URL`
- `SPRING_AI_OLLAMA_CHAT_OPTIONS_MODEL`
- `MILVUS_HOST`
- `MILVUS_PORT`
- `APP_DIAGNOSIS_SERVICE_URL`
- `APP_STARTUP_AUTO_BOOTSTRAP`

需要说明：

- 本机开发默认不会自动启用 MySQL
- 本机开发默认不会自动执行全量初始化
- 若未启用 MySQL，协同模块和满意度反馈会回退到本地状态文件；启用后会同步进入结构化表

如需自动初始化，可显式设置：

```powershell
$env:APP_STARTUP_AUTO_BOOTSTRAP='true'
```

## 5. 环境验证

### 5.1 后端编译验证

```bash
cd backend
mvn -q -DskipTests package
```

### 5.2 前端构建验证

```bash
cd frontend
npm install
npm run build
```

### 5.3 健康验证

```bash
curl http://localhost:8080/api/health
```

当依赖全部正常时，返回的 `status` 应为 `healthy`；如果部分依赖不可用，可能返回 `degraded`，但平台仍可能通过降级路径继续演示。

## 6. 常见问题

### 6.1 Docker 能启动，但后端提示依赖不可用

优先检查：

- `docker compose ps`
- `docker compose logs backend`
- `docker compose logs ollama`
- `docker compose logs milvus`

### 6.2 Ollama 没有模型

执行：

```bash
ollama pull qwen2.5:0.5b
```

### 6.3 本机启动后问答没有来源

确认三点：

- 文档样例是否已导入
- Milvus 是否可连接
- 是否执行过图谱 / 向量初始化

### 6.4 本机启动后没有看到求助或门店方案

确认两点：

- MySQL 已启用时，先确认 `APP_MYSQL_*` 配置和 `platform_store_profiles / platform_remedy_plans / platform_consultations` 是否正常
- MySQL 未启用时，再检查 `data/collaboration-state.json` 是否存在且可写
- 是否使用了默认演示账号并保留了种子数据
