# 自动化开发说明

## 目标

`scripts/auto-dev.ps1` 用来把当前仓库的自动化开发流程串起来：

- 读取 `tasks/*.task.json` 任务文件
- 可选执行一次实现命令
- 执行前端构建和后端打包
- 可选启动 `docker compose`
- 可选调用 `/api/system/init`
- 可选执行 `.smoke/run-smoke.ps1`
- 输出一份 JSON 和 Markdown 报告

这个版本的重点不是“让 AI 完全代替人写完整个项目”，而是把“生成代码 -> 验证 -> 汇报”这条链先固化下来，后面你可以把任何 AI 命令挂进 `implementCommand`。

## 任务文件格式

任务文件使用 JSON，推荐放在 `tasks/` 目录：

```json
{
  "title": "Document page refactor",
  "goal": "Refactor the document page without touching diagnosis code.",
  "allowedPaths": [
    "frontend/src/views/DocumentView.vue",
    "frontend/src/api/index.ts"
  ],
  "implementCommand": "",
  "baseUrl": "http://localhost:8080/api",
  "requireRealDiagnosisModel": false,
  "composeServices": [
    "diagnosis-service",
    "backend",
    "frontend"
  ],
  "checks": {
    "frontendBuild": true,
    "backendBuild": true,
    "composeUp": false,
    "systemInit": false,
    "smokeTest": false
  }
}
```

字段说明：

- `allowedPaths`: 这一轮任务允许改动的路径前缀。脚本会在执行前后做文件快照，发现越界改动就标记失败。
- `implementCommand`: 作为 PowerShell 命令执行。留空时，本轮只做验证和报告。
- `composeServices`: 当 `checks.composeUp=true` 时，追加到 `docker compose up -d --build` 后面。
- `checks`: 控制每个阶段是否执行。

## 常用命令

只做一轮干跑，检查配置是否正确：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\auto-dev.ps1 -TaskFile .\tasks\template.task.json -DryRun
```

执行一轮本地构建验证：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\auto-dev.ps1 -TaskFile .\tasks\full-validation.task.json
```

跳过容器和冒烟，只保留构建：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\auto-dev.ps1 `
  -TaskFile .\tasks\full-validation.task.json `
  -SkipCompose `
  -SkipInit `
  -SkipSmoke
```

强制覆盖任务文件里的实现命令：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\auto-dev.ps1 `
  -TaskFile .\tasks\template.task.json `
  -ImplementCommand "Write-Host 'replace with your AI or script command'"
```

## 报告输出

每次运行都会在 `reports/auto-dev/<timestamp>/` 下输出：

- `report.json`
- `report.md`
- `steps/*.stdout.log`
- `steps/*.stderr.log`

同时会更新：

- `reports/auto-dev/latest.json`
- `reports/auto-dev/latest.md`

另外，脚本会把 Maven 本地仓库默认放到仓库内的 `.cache/m2/repository`，这样在受限环境里也能跑后端打包，不依赖用户目录下的 `.m2`。

## 建议用法

推荐把它当成一个“自动开发编排器”而不是单纯脚本：

1. 先写一个任务文件，把目标和允许修改范围锁定住。
2. 如果你要接 AI，把 `implementCommand` 指向你的生成命令。
3. 让脚本统一做构建、初始化、冒烟和出报告。
4. 最后只对报告里的失败项和越界改动做人审。

这样会比“直接让 AI 自由发挥改整个仓库”稳定很多。
