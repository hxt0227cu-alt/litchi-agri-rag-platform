# 用药剂量安全校验评审

## 1. 评审目标

评估当前“门店方案推荐与风险提醒”模块是否已经进入需要独立剂量规则引擎的阶段，并给出当前版本的边界结论。

## 2. 当前实现定位

- 当前页面提供的是“门店方案摘要 + 风险提醒 + 问答/求助跳转”。
- 当前内容强调病害/虫害场景、药剂方向、轮换原则、安全间隔期和巡园管理。
- 当前内容没有输出按树龄、亩数、稀释倍数、施药设备、采收期反推后的精确剂量结果。

结论：

- 当前模块本质上是“咨询辅助页”，不是“精确处方系统”。
- 因此在当前答辩版本中，不应把它描述为自动剂量决策模块。

## 3. 是否必须拆分独立规则模块

### 当前答辩/课程验收范围

- 结论：`暂不需要`

原因：

- 需求文档中提出了“农药剂量安全校验”目标，但当前系统的门店方案页面主要承担的是建议展示与风险提示。
- 只要前端和文档中明确说明“需遵循标签、当地植保要求和专业人员判断”，当前版本仍可作为合理的教学与演示实现。

### 若继续走向生产化使用

- 结论：`建议拆分`

建议独立规则模块至少补充以下输入：

- 作物品种与生育期
- 目标病虫害与发生程度
- 树龄、株数、亩数或冠幅
- 施药方式、稀释倍数、施药设备
- 采收期与安全间隔期
- 当地登记标签与禁限用要求

## 4. 当前版本建议边界

- 可以说：系统提供“方案建议、沟通提醒和风险提示”。
- 不应说：系统可以自动给出“精确剂量处方”。
- 对涉及剂量、混配、采收期、安全间隔期的问题，应该优先引导用户查看标签说明，并在复杂场景下转人工或转智能问答进一步核实。

## 5. 已执行动作

- 已在解决方案与门店方案展示中补充“安全使用边界”提示。
- 已在收尾任务清单中将该项转为有结论的评审任务，而非无限期悬空事项。

## 6. 最终结论

- 当前答辩版本：不必新增独立剂量规则引擎，但必须明确“建议性质”和“非精确处方”边界。
- 后续扩展版本：若系统要承担真实配药决策职责，应单独设计剂量规则模块，并配套审计、约束条件和免责声明。
- 对应的拆分建议和输入/输出边界已整理在 `docs/剂量规则模块设计.md`。
