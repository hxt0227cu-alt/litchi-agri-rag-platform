# 安全与运维专项检查

## 1. 当前结论

### 1.1 用户认证数据

- 用户密码不是明文存储，而是采用 `PBKDF2WithHmacSHA256` + 随机盐后保存到 `platform_users.password_hash / password_salt`。
- 相关实现位于 `backend/src/main/java/com/litchi/auth/AuthService.java`。
- 当前可以认定“密码存储”已经满足基础加固要求。
- 会话 token 由服务端创建并设置过期时间，当前默认有效期为 7 天。

### 1.2 配置与敏感地址展示

- 系统设置接口对带有 `password=` 的连接串做了脱敏展示，避免直接暴露依赖密码。
- 相关实现位于 `backend/src/main/java/com/litchi/controller/SystemController.java`。

### 1.3 操作日志策略

- 当前版本已补充后端审计日志拦截器，对主要写操作输出统一审计日志。
- 审计日志记录处理器、方法、路径、状态码、结果、耗时、来源 IP、用户信息。
- 审计日志不记录密码、token、请求体等敏感内容。

### 1.4 跨域与访问边界

- 后端 CORS 已改为可配置白名单，默认仅放行本机常用开发与演示来源：`localhost`、`127.0.0.1`、`5173`。
- 相关配置项为 `APP_CORS_ALLOWED_ORIGIN_PATTERNS`，适合后续按环境进一步收紧。

## 2. 已落实项

| 项目 | 现状 | 结论 |
| --- | --- | --- |
| 密码存储 | PBKDF2 + 随机盐 | 已落实 |
| 系统连接信息脱敏 | 已对带密码的 URL 做展示脱敏 | 已落实 |
| 写操作审计日志 | 已落地统一拦截记录 | 已落实 |
| CORS 白名单 | 已从全开放改为可配置白名单 | 已落实 |

## 3. 业务数据存储现状

| 数据项 | 当前存储方式 | 安全结论 |
| --- | --- | --- |
| 用户密码 | MySQL `password_hash/password_salt` | 已满足基础哈希存储要求 |
| 会话 token | 服务端会话表 `platform_sessions` | 可用，但若面向生产仍建议进一步加固 |
| 聊天记录 | MySQL `platform_chat_messages` | 当前为业务可用性优先，未做字段级加密 |
| 文档元数据与分块 | MySQL `platform_documents`、`platform_document_chunks` | 当前满足检索与演示需求 |
| 门店协同 | MySQL `platform_store_profiles`、`platform_remedy_plans`、`platform_consultations` | 已完成结构化落库，保留 JSON 回退副本 |
| 满意度反馈 | MySQL `platform_feedback_records` | 已完成结构化落库，保留 JSON 回退副本 |

## 4. 仍需补充确认项

| 项目 | 当前现状 | 后续动作 |
| --- | --- | --- |
| 会话 token 存储策略 | 会话 token 仍用于服务端会话识别，默认过期时间为 7 天；前端当前保存在本地存储 | 若继续生产化，建议转 HttpOnly Cookie 或服务端短期票据 |
| 聊天记录与反馈内容 | 业务数据当前以业务可用性为主，未做额外字段级加密 | 结合真实部署范围决定是否增加字段级加密 |
| 日志保留周期 | 审计日志已落地到应用日志文件 | 当前建议保留 30 天；生产化时补日志切割、归档和脱敏审计流程 |
| 敏感数据分级 | 已避免记录密码、token 和请求体，但尚未形成分级矩阵 | 补充字段分级、导出审批和删除策略说明 |

## 5. 建议

- 若项目目标是答辩与课程验收，当前密码哈希与审计日志已经能支撑“有策略、有实现”的说明。
- 若项目后续继续扩展到生产化场景，优先补充 token 存储加固、日志保留策略和敏感业务字段分级管理。
