# 部署文档

## 1. 组件说明

平台由以下服务组成:

- `frontend`: Vue 前端
- `backend`: Spring Boot 后端
- `mysql`: 平台账号、历史、评测、文档状态主存储
- `neo4j`: 知识图谱
- `milvus`: 向量检索
- `ollama`: 大模型服务
- `diagnosis-service`: 病害识别服务

其中:

- MySQL 负责平台业务状态
- Neo4j 和 Milvus 继续承担图谱与向量能力
- 后端会把本地 JSON 状态文件作为 MySQL 的回退

## 2. 环境要求

- Docker 24+
- Docker Compose 2.20+
- 建议内存 16GB 以上
- 如果需要本地病害模型推理，可额外准备 GPU 环境

## 3. 环境变量

先复制模板:

```bash
cp .env.example .env
```

关键变量如下:

```env
MYSQL_ROOT_PASSWORD=root123456
MYSQL_DATABASE=litchi_platform
MYSQL_USER=litchi
MYSQL_PASSWORD=litchi123456

APP_MYSQL_ENABLED=true
APP_MYSQL_URL=jdbc:mysql://mysql:3306/litchi_platform?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
APP_MYSQL_USERNAME=litchi
APP_MYSQL_PASSWORD=litchi123456

NEO4J_AUTH=neo4j/litchi123456
OLLAMA_CHAT_MODEL=qwen2.5:0.5b
MILVUS_COLLECTION_NAME=litchi_knowledge
DIAGNOSIS_MODEL_PATH=/models/yolov8-litchi.pt
DIAGNOSIS_STRICT_MODEL=false
```

## 4. 一键启动

```bash
docker compose up -d --build
```

常用检查命令:

```bash
docker compose ps
docker compose logs -f backend
docker compose logs -f mysql
```

## 5. 访问地址

- 前端: `http://localhost`
- 后端 API: `http://localhost:8080/api`
- Neo4j Browser: `http://localhost:7474`
- MySQL: `localhost:3306`
- 病害识别健康检查: `http://localhost:8090/health`

## 6. 初始化与演示准备

平台启动后，可以调用以下接口完成演示准备:

```bash
curl -X POST "http://localhost:8080/api/system/init?scope=all"
curl -X POST "http://localhost:8080/api/system/demo/bootstrap"
```

演示账号:

- `farmer / demo123`
- `technician / demo123`
- `shopkeeper / demo123`

## 7. 本机开发模式

### 后端

```bash
cd backend
mvn spring-boot:run
```

### 前端

```bash
cd frontend
npm install
npm run dev
```

开发模式下:

- 若未设置 `APP_MYSQL_ENABLED=true`，后端会只使用本地 JSON 状态文件
- 若启用 MySQL，则后端会优先使用 MySQL，并同步更新本地状态文件

## 8. 排障

### MySQL 未连通

- 检查 `docker compose ps mysql`
- 检查 `APP_MYSQL_URL`、`APP_MYSQL_USERNAME`、`APP_MYSQL_PASSWORD`
- 查看 `docker compose logs -f mysql`

### 后端健康状态为 `degraded`

`/api/health` 返回 `degraded` 通常表示以下至少一个组件不可用:

- Neo4j
- Milvus
- Ollama
- diagnosis-service

先检查:

```bash
docker compose ps
docker compose logs -f backend
```

### 文档上传成功但问答无来源

优先检查:

- 文档是否成功切块并入索引
- Milvus 是否正常启动
- 上传文档是否为可提取文本的格式

## 9. 数据说明

- MySQL 数据卷: `mysql_data`
- Neo4j 数据卷: `neo4j_data`
- Milvus 数据卷: `milvus_data`
- Ollama 数据卷: `ollama_data`
- 后端本地数据卷: `backend_data`

如需完整清空数据:

```bash
docker compose down -v
```
