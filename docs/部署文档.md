# 部署文档

## 1. 部署说明

当前项目支持两种运行方式：

- Docker 全栈部署：适合答辩演示、快速验收和一键拉起依赖
- 本机开发部署：适合调试前端、后端和识别服务

默认推荐使用 Docker 全栈部署，因为它已经包含模型拉取、样例数据引导和依赖服务编排。

## 2. 服务组成
`docker-compose.yml` 当前编排的服务包括：
- `frontend`：Vue 3.5.25 + TypeScript 5.9.3 前端（Nginx 1.27）
- `backend`：Spring Boot 3.2.0 + Java 17 后端
- `mysql`：MySQL 8.0，账号、会话、聊天、评测、文档、协同、反馈主存储
- `neo4j`：Neo4j 5.15-community，知识图谱
- `etcd`：Etcd v3.5.5，Milvus 配置管理依赖
- `minio`：Minio，Milvus 对象存储依赖
- `milvus`：Milvus v2.3.3，向量检索
- `ollama`：Ollama，本地大模型服务（默认模型：qwen2.5:0.5b）
- `ollama-model-init`：自动拉取默认模型
- `diagnosis-service`：Python 3.11 诊断服务（Pillow >= 10.0.0 + Ultralytics >= 8.3.0）

其中：
- MySQL 承载核心结构化业务数据
- 后端会把本地 JSON 状态文件作为 MySQL 和弱依赖环境下的回退
- 诊断服务支持三级降级机制（ultralytics-yolo → dataset-vision → demo-rule）

## 3. 环境要求

- Docker 24+
- Docker Compose 2.20+
- 建议内存 16GB 以上
- 如需本机直接运行 YOLO 推理，可额外准备 GPU 或完整 Python 依赖环境

## 5. 一键启动

```bash
docker compose up -d --build
```

Windows PowerShell 也可以直接执行：

```powershell
Copy-Item .env.example .env
docker compose up -d --build
```

常用检查命令：

```bash
docker compose ps
docker compose logs -f backend
docker compose logs -f diagnosis-service
docker compose logs -f ollama
```

## 6. 访问地址

- 前端：`http://localhost:8081`
- 后端 API：`http://localhost:8080/api`
- 后端健康检查：`http://localhost:8080/api/health`
- Neo4j Browser：`http://localhost:7474`
- MySQL：`127.0.0.1:3306`
- 识别服务健康检查：`http://localhost:8090/health`

说明：根目录 `docker-compose.yml` 将前端容器的 80 端口映射到宿主机 `8081`，因此浏览器访问地址是 `http://localhost:8081`。

## 7. 自动初始化与演示准备

Docker 环境默认开启以下能力：

- 自动拉取 Ollama 默认模型 `qwen2.5:0.5b`
- 自动初始化知识图谱
- 自动初始化向量集合
- 自动导入平台样例文档
- 自动准备可直接演示的推荐问题与工作台数据

因此在默认配置下，通常不需要额外手动执行初始化接口。

如需手动重建，可使用技术员 token 调用：

```bash
curl -X POST "http://localhost:8080/api/system/init?scope=all" ^
  -H "Authorization: Bearer <token>"

curl -X POST "http://localhost:8080/api/system/demo/bootstrap" ^
  -H "Authorization: Bearer <token>"
```

## 9. 数据卷说明

- `mysql_data`：MySQL 数据
- `neo4j_data`：Neo4j 数据
- `neo4j_logs`：Neo4j 日志
- `etcd_data`：Milvus 依赖数据
- `minio_data`：Milvus 对象存储数据
- `milvus_data`：Milvus 数据
- `ollama_data`：Ollama 模型数据
- `backend_data`：后端文档原件、回退状态文件、协同和反馈数据

需要说明：

- `backend_data` 中会保留文档原文件和 `data/*.json` 状态文件
- 门店协同和满意度反馈的主数据会进入 MySQL；`backend_data` 中对应 JSON 文件继续保留回退副本

## 10. 常见排障

### 10.1 MySQL 未连通

优先检查：

- `docker compose ps mysql`
- `APP_MYSQL_URL`
- `APP_MYSQL_USERNAME`
- `APP_MYSQL_PASSWORD`
- `docker compose logs -f mysql`

### 10.2 后端健康状态为 `degraded`

`/api/health` 返回 `degraded` 通常表示以下至少一个组件不可用：

- Neo4j
- Milvus
- Ollama
- diagnosis-service

优先检查：

```bash
docker compose ps
docker compose logs -f backend
```

### 10.3 问答没有来源

优先检查：

- 文档样例是否已导入
- Milvus 是否正常启动
- 文档是否已完成切块和索引同步

### 10.4 识别服务处于演示模式

优先检查：

- `models/yolov8-litchi.pt` 是否正确挂载
- `diagnosis-service` 容器日志中是否加载到模型
- 是否误开启了 `DIAGNOSIS_STRICT_MODEL=true`

### 10.5 协同或反馈数据重启后丢失

优先检查：

- MySQL 中 `platform_store_profiles`、`platform_remedy_plans`、`platform_consultations`、`platform_feedback_records` 是否存在且有数据
- `backend_data` 数据卷是否正常挂载
- 后端容器内 `data/collaboration-state.json` 和 `data/feedback-state.json` 是否存在，用于回退与副本恢复

## 11. 清空数据

如需完整清空 Docker 数据：

```bash
docker compose down -v
```

执行后会清除 MySQL、Neo4j、Milvus、Ollama、本地回退文件和协同数据，请谨慎操作。
