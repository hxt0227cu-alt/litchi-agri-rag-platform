# 答辩演示说明

## 一键启动

在项目根目录执行：

```powershell
.\scripts\run-demo.ps1
```

如果你想在启动前重新构建一次前后端，可以执行：

```powershell
.\scripts\run-demo.ps1 -Build
```

启动完成后，默认访问地址为：

- 前端演示页：`http://127.0.0.1:5173`
- 后端健康检查：`http://127.0.0.1:8080/api/health`
- 识别服务健康检查：`http://127.0.0.1:8090/health`

演示结束后执行：

```powershell
.\scripts\stop-demo.ps1
```

## 推荐演示顺序

### 方案 A：完整三角色闭环

1. 技术员登录 `technician`
   - 进入技术支持台或系统状态页
   - 用一句话说明平台是“农户发起问题、门店承接方案、技术员持续优化”的三角色系统
2. 农户登录 `farmer`
   - 进入农户工作台
   - 展示学习课堂或病害识别
   - 进入智能问答，展示来源卡片和图谱命中
   - 进入解决方案页，展示推荐原因、门店信息和风险提醒
   - 提交一条求助，进入“我的求助”
3. 门店登录 `shopkeeper`
   - 进入门店工作台
   - 打开待处理求助，展示刚才的求助记录
   - 把状态更新为“已联系”或“已完成”
   - 可补充展示配药方案库或高频病症看板
4. 技术员再次登录 `technician`
   - 打开知识文档页或研判图谱页
   - 打开评测中心，说明如何持续优化 AI 回答质量

### 方案 B：时间较紧时的精简链路

1. 技术员说明系统结构和依赖状态
2. 农户演示识别、问答、方案推荐
3. 门店演示收件箱和状态更新

## 推荐演示话术

- 不要把系统只讲成“问答平台”，要强调当前版本已经形成协同闭环。
- 讲农户侧时，重点突出“识别/问答不是终点，后面还能进入门店方案和求助流转”。
- 讲门店侧时，重点突出“门店不是静态信息页，而是能维护方案、接收求助、观察趋势”。
- 讲技术员侧时，重点突出“文档、图谱、评测、系统状态共同支撑后续优化”。

## 当前默认演示模式

- 问答模块：即使 Ollama 不在线，也会回退到本地保障回答
- 图谱模块：即使 Neo4j 不在线，也会使用内置演示图谱
- 检索模块：即使 Milvus 不在线，也会回退到本地分块检索
- 识别模块：若 `models/yolov8-litchi.pt` 不可用，会自动回退到数据集特征匹配或规则模式

## YOLO 模型说明

识别服务已经支持自动加载 YOLO 权重文件。只要模型文件位于以下路径：

```text
models/yolov8-litchi.pt
```

启动 `diagnosis-service/server.py` 时就会优先切换到 `ultralytics-yolo` 模式。

当前仓库已经包含 `models/yolov8-litchi.pt`。若本机已安装 `ultralytics` 依赖，识别服务会优先使用 YOLO 推理；若依赖缺失或模型加载失败，则自动回退到演示模式，不影响答辩流程。

## 建议备选页面

如果现场网络、模型或依赖状态不理想，优先保留以下页面：

- 农户工作台
- 智能问答
- 解决方案
- 门店收件箱
- 技术支持台

这些页面最能体现当前版本的三角色协同定位。
